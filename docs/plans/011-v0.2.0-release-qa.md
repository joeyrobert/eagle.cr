## Doubts, why they matter, and how to address them

### 1. Touch has never been run on a real device
- Why: only synthetic events (`Script.touch_*`) and headless Chrome were used. Real browsers differ on touch ids, touchcancel, pull to refresh, double tap zoom, address bar resize, and coordinates under browser zoom and high DPI.
- Check: serve the touch example (`script/build-web.sh examples/touch/main.cr`) and open it on a phone or with Chrome device emulation plus a real touch screen if possible. Test in iOS Safari and Android Chrome if available.
- Verify: drag cards, pinch and twist the star with two fingers, joystick and fire button at the same time (3 fingers), lifting fingers in different orders, switching tabs mid gesture, rotating the device, page does not scroll or zoom or pull to refresh, no text selection callout.
- Known gap to confirm: a Button keeps its hover highlight after the finger lifts (mouse emulation sends no mouse-leave). Decide whether that is acceptable.
- Test to add: any bug found becomes a `Script.touch_*` spec.

### 2. `Fiber.syscall` is redefined to fix the GL crash (PR #53)
- Why: `src/eagle/platform/sdl.cr` reopens Crystal's `Fiber` and overrides a `:nodoc:` stdlib method so the main fiber never moves threads. It fixes a proven crash (GL context and the macOS event loop belong to the original thread) but is fragile across Crystal upgrades, and it changes scheduling for every blocking file read.
- Check: confirm the override still compiles and is a no-op-safe on Linux and Windows builds (CI covers Linux only). Confirm audio callbacks and any threaded code (asset loading, Ogg decoding) still behave. Confirm the override does not get compiled into the wasm build.
- Check: pin the Crystal version in CI and the docs, and add a spec or compile-time guard that fails loudly if `Fiber.syscall` changes signature in a newer Crystal (for example a `{% if compare_versions(Crystal::VERSION, "1.22.0") >= 0 %}` note or a spec that calls `Fiber.syscall { }`).
- Cleanup: the comment above the override is multi-line; the owner prefers single-line comments.
- Regression test exists: `spec/integration/thread_migration_spec.cr` (fails with a segfault at 0x1508 without the override). Keep it.
- Alternatives were prototyped and rejected (2026-09-18): an isolated execution context cannot host SDL on macOS (SDL_Init for video crashes off thread 0, even on a plain Thread.new), and Crystal 1.21 has no runtime setting to stop the monitor from detaching the scheduler after a 10ms syscall. The only supported alternative is the compile flag `-Dwithout_mt` (Fiber.syscall becomes a plain yield, no monitor thread), but the builder must pass it (CLI, scripts, CI, every game author) and it removes Fiber::ExecutionContext. Decision: keep the small override. Follow-up: single-line comment, Crystal version guard, and document `-Dwithout_mt` as an alternative.

### 3. The crash fix was proven for the traced cause, not for every crash
- Why: the crashing seeds shared the thread-migration cause. A second fault address (0x1280) and one "Process hit a breakpoint" were folded into the same explanation without separate proof, and one 3D shadow spec failure was a separate Scene3D state leak (fixed).
- Check: run the full suite 20+ times with random seeds on macOS (`crystal spec`, plain, no `--order`) and on Linux CI. Log every failure seed. Any crash outside the migration explanation gets its own issue.
- Check: run the suite while the machine is busy (parallel builds) since the 10ms migration threshold is timing dependent.

### 4. Windows is untested at link and run time
- Why: roadmap known gap. CI builds the Windows CLI artifact but nothing runs the engine there.
- Check: on a Windows machine or VM, install from the release artifact, run `eagle init`, build and run a 2D and a 3D example, run `eagle export exe`, and run the installer script. Verify GL context creation and audio.
- If no Windows machine is available, say so in the release notes as "Windows is best effort".

### 5. Merged main has not been exercised as a whole
- Why: each PR was verified alone and merged into an older main. Roadmap and README conflicts were resolved by hand.
- Check: on the final main run `crystal spec`, `script/check_doc_examples.cr`, `script/build-site.sh` (confirm every example appears, touch, voxel, fps, algorithms), and `script/build-web.sh` for every example (not just one). Screenshot every example natively with `EAGLE_FRAMES=n EAGLE_SCREENSHOT=x.png` and eyeball them for regressions, especially the ones that use text (text batching changed how shapes and text share textures).
- Test to add: a spec that iterates all examples with a few frames headless (a smoke test) if one does not exist.

### 6. Text batching changed shape drawing (PR #54)
- Why: rects, lines and circles now sample a white texel inside the font atlas. Pixel equality was proven for two fonts and one scene, but not for antialiased edges under scaling, rotation, camera zoom, or clip rects, and not for every font size.
- Check: render a matrix of scale, rotation, clip and font size before and after (compare to a build of v0.1.x or pre-#54 main) and diff the pixels. Look for edge bleeding (linear filtering can bleed neighboring atlas pixels into a small white block).
- Test to add: bleed test at several scales; an atlas-packing spec that asserts the white block has a padding border.

### 7. Physics3D defaults and edge cases (PR #48)
- Why: sleeping is off by default; jointed bodies never sleep; dynamic concave meshes, joint limits, motors and springs were cut. Two real solver bugs were found late, which suggests more may exist.
- Check: stress test stacking (box pyramid, capsule pile), fast bodies against mesh floors (tunneling), a ragdoll-like chain of joints, and long runs (10 minutes) for drift or explosions. Compare frame times with sleeping on and off.
- Test to add: a deterministic scenario spec for each bug found (pile settles below a velocity threshold within N steps, no NaNs).

### 8. UI widgets (PR #49) and touch
- Why: `ScrollContainer` holds one child, has no kinetic scrolling and no touch drag scrolling. `OptionButton` has no type-to-search. Rich text has no italics or images.
- Check: use all three in a real layout (a long list in a scroll container, a drop-down near the screen edge, rich text with links, nested scroll containers), with mouse, keyboard and touch. Confirm the drop-down popup closes on outside click and Escape and stays on screen near edges.
- Follow-up issue to file: kinetic (flick) scrolling for `ScrollContainer` (mentioned in PR #50 as a follow-up).

### 9. Web backend gaps
- Known: no IME or clipboard on web (#30, may land before the release). Pointer lock needs a user gesture.
- Check: type accented and CJK text on web builds (expect broken until #30), copy and paste, and fullscreen. Test in Chrome, Firefox and Safari. Confirm audio starts after the first gesture on each.
- Release notes must list what does not work on web.

### 10. Release mechanics
- Check: `install.sh`, `install.ps1`, the Windows Inno installer, `eagle --version`, and the homepage install snippet all say 0.2.0 and the installer actually downloads the tagged artifacts once the tag exists. The tag has not been pushed yet; test the installers after the release workflow finishes, from a clean machine or container.
- Check: the release workflow artifacts (macOS, Linux, Windows) each run `eagle --version` and `eagle init` successfully.
- Check: `docs/plans/010-roadmap.md` known-gaps section matches reality after all merges.
- Consider: mark the GitHub release notes with the known limitations from this doc (touch untested on device, Windows best effort, web IME and clipboard).

## Overall bar for tagging
Tag v0.2.0 when: the full suite is green on 20 random seeds on macOS and once on Linux CI, all examples build for native and web and screenshot sanely, touch works on at least one real phone, and the known limitations are written into the release notes. Anything that fails one of those becomes a GitHub issue and is either fixed or listed as a known limitation.
